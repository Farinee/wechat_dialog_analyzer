# 难不成Ta真的喜欢我？
想知道Ta喜欢你还是讨厌你吗？还在一张张截图问AI吗？你out了! 
除了提取聊天记录以外，本工具相比于其他工具拥有了多模态支持，能自动识别表情包及图片(不喜欢老是发语音的人所以不支持语音条识别)。
相比于私聊分析，本工具最大的特点是支持RAG检索，由于群聊的消息动则数万条并且充斥着大量垃圾信息。 RAG能显著降低输入token消耗(喜欢我一个问题1Mtoken吗)
目前仅支持 deepseek api， 调用 deepseek v4 flash 进行文本和多模态分析。

## 启动

双击根目录的 `run.bat`，或者在 PowerShell 中运行：

```powershell
Set-Location 'D:\pythonprograms\chat'
& 'D:\conda\python.exe' '.\main.py'
```

你提供的 `D:\conda\_conda.exe` 是 Conda 管理器，它的基础环境解释器为 `D:\conda\python.exe`。也可以通过它启动：

```powershell
& 'D:\conda\_conda.exe' run --prefix 'D:\conda' --no-capture-output python '.\main.py'
```

在 PyCharm 中，把解释器设为 `D:\conda\python.exe`，运行文件设为根目录的 `main.py`，工作目录设为本项目根目录。

## 使用

1. 保持电脑版微信已登录，启动程序。
2. 在左侧选择一个群聊；如需个人消息，切换到「个人」后选择一个联系人。再次选择其他聊天会切换当前范围，旧存档继续保留。
3. 设置起始、结束日期，首尾日期均包含在内，不能选择未来日期。
4. 在「API 设置 → 图片与表情」中填写密钥后启用素材解读，可单独开关静态表情识别。
5. 点击「聊天解码并储存」，把所选日期的文字、图片和静态表情解读保存到本地；动态表情只保留占位。
6. 点击「读取本地原文」后，选择预览日期，或用「上一天／下一天」切换有本地消息的日期。默认显示范围内最新一天，每页最多 200 条，支持翻页；两个资料标签页显示同一天、同一页。预览日期不改变检索和同步范围。「原始资料层」显示留存正文、媒体 XML、状态和素材文件位置；「可检索文字层」显示整理后的文本和去重的 AI 素材词典。检索后两页对应本次引用，选择预览日期可返回本地存档。超长预览会标注截取，完整数据保留。原始媒体 XML 不送入模型；浏览不连接微信、不重复解码。点击「打开文本存档目录」查看完整的按天文本。
7. 在提问按钮旁选择「RAG 检索」或「全文分析」，输入问题后点击「读取所选范围并分析」（Ctrl+Enter）。RAG 完整发送当前范围内全部关键词匹配原文及去重素材解读，只压缩较早问答；容量不足时先减少问答历史，再缩小补充的前后消息窗口并显示减少量。匹配原文本身仍超限时停止分析并提示缩小范围，不省略匹配消息。全文分析一次发送所选范围全部已保存消息，容量不足时排除较早整条记录并提示范围。两种模式都保留本地完整资料。回答支持 Markdown；接收过程中向上滚动阅读时保留当前位置，停在底部时自动跟随新内容；每轮可点击「查看本轮引用」核对证据。
8. 对话按聊天和起止日期自动保存，重启后恢复。上方下拉框切换历史对话，「新对话」保留旧会话并开始新上下文。草稿自动保存，发送前保存问题，回答及引用先落盘再展示；中断保留明确标记的未完成片段，不自动重发。「导出对话」保存当前会话的完整 Markdown、API 返回的模型思考和各轮引用，也包含较早中断请求已收到的正文与思考片段，按提问顺序排列并标记未完成。全文模式提供最近最多10轮、约2万字符历史；RAG模式使用较早历史摘要、相关旧问答和最近三轮，过长时节选。历史助手回答均不作为微信事实证据。

开启模型思考且 API 返回 `reasoning_content` 时，最终分析的思考原文会独立保存，导出的 `.md` 增加「模型思考（API 返回）」一节，与正式回答分开。接收期间累计保存思考片段，断线、取消或输出超限后仍可导出，标明未完成；即使只收到思考、还没有正文也支持导出。重启不会重新发送请求。思考内容不进入后续问答上下文、历史摘要或事实证据。未开启思考、API 未返回该字段，或旧版已丢弃的历史思考不会补写。查询规划和历史摘要等辅助调用的思考不混入正式分析。

聊天名称优先使用本机通讯录中的备注和真实群名。对于本机缺少群名的群，显示「未命名群（成员摘要）」。已移除修改显示名称功能，刷新列表时不再应用以前的本地名称覆盖设置。

消息时间、历史日期筛选、同步时间和 DeepSeek 的日期理解统一使用北京时间（UTC+8）。

聊天列表默认仅显示同时满足「消息数至少 1000 条、消息内容至少 50 KB」的聊天，并按内容大小从大到小排列。列表会显示条数和大小，可取消筛选查看全部，或切换为按条数排序。

这些统计来自微信本机保存的完整历史，独立于导入起始日期。大小是消息正文字段的存储字节数（中文按 UTF-8 字节计），不包含图片、语音和其他附件文件。筛选只影响列表显示，不删除原始消息或自动取消已保存的聊天选择；隐藏的已选聊天会在列表下方提示。

启动优先恢复本地聊天列表和上次保存的日期，不自动导入消息或调用 VLM。首次没有本地聊天信息时，从微信加载列表；后续需要更新名单或统计时，点击「从微信刷新聊天列表」。旧版数据没有完整列表缓存时可先恢复已保存的聊天信息，统计显示「—」，刷新后补齐。

## 日期存档和增量同步

- 文本保存在 `data/transcripts/<聊天稳定编号>/YYYY-MM-DD.txt`。文件头包含聊天名称、日期和北京时间，每条消息包含时间、发言人、类型及稳定消息 ID。图片/表情以素材编号引用，文件末尾的素材词典保存一份 AI 解读；重复发送事件全部保留。尚未解读或不符合条件的素材保留状态说明。
- SQLite 保存同一份文字的本地检索索引、已完成日期区间和图片缓存。提问、切换聊天、变更日期及预览原文均读取本地数据，不连接微信，不重复解码微信消息或图片。手动编辑文本文件不会自动回写索引。
- 已完成的历史日期直接复用；扩大日期范围只导入缺失的部分，切换到更早日期也可补导。消息按账号、聊天、分片和本地消息编号去重，重叠同步不会产生重复条目。
- 包含今天时，仅记录到本轮同步时间；下次点击同步补入后续消息，并复查最近五分钟以接收延迟消息。同步仍需读取微信的加密数据库，新内容可能触发源数据库快照解密；后续本地检索不再解密。
- 微信后来从手机补下来的旧消息，或较早时间的消息修正，可勾选「重新检查已存日期」后同步所选范围。已有消息会去重或更新，完成的图片解读继续复用。
- 每次只重写有变化的日期文件，并先写临时文件再替换。读取分片或写文件失败时保留已导入内容，不将失败区间标为完成；重试可继续补齐。图片解读失败独立保留重试状态，文字存档仍可检索。
- 当前选择的聊天与日期是检索的硬边界，模型生成的检索条件不能扩大这个范围。尚未同步的部分会在「同步范围」提示，回答只依据已有本地内容。
- 全文分析把范围内消息按时间从早到晚交给模型。消息总数和最早／最晚时间直接统计全部符合条件的本地记录，不受输入截断影响。模型若因容量不足没有收到更早的原文，只能引用本地统计，不能声称读过已排除的原文。RAG 完整提供符合关键词和日期条件的原文；匹配条件外的消息未提供时，不能声称已经阅读所选范围全部消息。

## RAG 压缩

本版提供关键词 RAG、全部匹配原文和问答历史摘要。向量编码和向量检索尚未启用；现有全文分析继续保留。可在提问按钮旁直接切换，或通过「API 设置 → 模型与推理」保存模式。已取消独立的 RAG 输入 token 预算、分块命中数量限制和原文节选；旧配置中的 `rag_input_tokens` 不再生效。

提问时只读取已经保存的 SQLite 消息和素材文字，不打开微信，不重新解码或调用 VLM。先根据当前问题、近期问答和历史摘要规划关键词，再在固定聊天和日期内检索；多个关键词为 OR 关系，完整发送全部匹配消息，并为每个命中补入前后对话。默认向前、向后各最多20条，单侧不超过15分钟，连续消息间隔超过5分钟则分段；容量不足时自动逐级缩为各10、5、2、1或0条，明确显示原窗口、实际窗口及减少的上下文数量，窗口为0表示只有关键词命中。重叠或相接的窗口在连续段内合并，消息去重后按北京时间从早到晚排列。窗口只表示时间邻近，不能保证同一话题或完整讨论；模型需结合提问、短回复、否定与更正判断，不能只看孤立命中。正文及所有关联素材解读均不节选。关键词为空时提供检索日期内全部本地消息。所有前后对话也严格遵守当前聊天及本轮收窄后的日期；匹配、上下文和统计来自同一读取快照。素材解读按实际素材编号复用，各次发送事件分别保留。界面分别显示所选范围总数、关键词匹配数、补充上下文数及总提供数；引用区按对话片段分段，逐条标记关键词命中或补充上下文。提供全部匹配消息不代表阅读了窗口外全部消息，原始存档保持完整。

分块和关键词索引均在本地生成，所有聊天共用 `data/rag.sqlite3`。每条消息按账号和聊天归属只保存一份索引，查询时再严格过滤当前聊天及日期；不必为每个群、联系人或日期范围单独建库。分块使用固定半小时时间段和内容哈希判断变化，再按长度切块。缩小或重叠选择日期复用已有分块，扩大日期时补充尚未建立索引的部分；新增消息、补入旧消息或保存新的素材解读后，只重建变化的时间段。其他日期和聊天的缓存继续保留。每次提问检查所选范围的本地快照，更新在事务内发布；中断会回滚，重试可继续。切换文字模型可能因分词规则变化而重新分块，无需重新识别图片。

首次使用新版 RAG 时，旧版按日期范围保存的索引会在本地合并、去重；未变化的分块直接迁移。迁移不连接微信或调用模型，原文、素材解读、对话和摘要均保留。每个查询范围仍须经过本地消息快照校验，不能将索引中其他日期的数据计入当前统计或证据。

RAG 保留最近三轮问答，较早历史用 DeepSeek 生成不超过容量的摘要；摘要包含主题、人物项目、用户要求、结论的不确定性和待解决问题。摘要按范围及会话缓存，后续只纳入新增的较早轮次，另可检索相关旧问答。过长的近期内容会显式标注节选，完整问答仍在 `data/conversations.sqlite3`。摘要与历史助手回答只用于衔接追问，不作为本轮微信事实证据。摘要 API 调用只在用户提问时发生；重启不会自动发送，原缓存相同则复用。

规划、摘要和最终回答均检查全局单次输入上限、上下文窗口、至少25%窗口余量、预留输出与32MiB本地请求体保护。RAG 全部匹配原文和前后对话超过容量时，先减少附带问答历史，再从已捕获的同一索引快照中逐级缩小前后窗口，完整保留全部关键词命中及其素材解读；减少量写入回答开头和引用范围，并作为模型输入提示。若匹配原文本身仍超限，则停止原文分析，分别显示输入token超限或本地请求体超限，数字带千位分隔及万单位，提示缩小日期或具体化关键词；不会仅发送部分匹配原文。原始消息和完整对话始终保留在本地。服务端拒绝过长输入也不自动缩减匹配原文重试。最终回答继续使用流式接收、片段持久化和取消机制。每轮引用保存输入估算、索引更新数量、摘要覆盖轮数与实际证据。摘要和规划也会产生 API 用量，因此小范围任务未必比全文模式节省，实际效果需结合问题评估。

原有文件保留；索引缓存可在关闭程序后删除并从本地消息重建。删除 `rag.sqlite3` 也会移除摘要缓存，再次提问时可能重新调用摘要接口。需要完整梳理某段时间的全部讨论、遗漏或矛盾时，选择全文分析。
- 从旧版本升级会保留索引、设置和加密密钥，并为已有消息生成文本。旧版没有完整日期覆盖凭据，因此首次同步所选范围会核实一次，之后复用覆盖记录。

## 高 DPI 显示

程序在创建窗口前启用 Windows DPI 感知，根据窗口所在屏幕的实际 DPI 缩放字体、按钮间距、输入框、聊天列表行高与列宽。窗口初始尺寸按当前屏幕可用工作区限制，避开任务栏；移动主窗口到不同缩放的显示器时，会重新检查并更新界面尺寸。

4K 屏幕配合 175% 等系统缩放时，无需另外修改 Python 的兼容性选项。可用空间较小时，左侧操作区和 API 设置中的表单可以滚动，保存按钮保留在窗口底部。更新代码后需要关闭旧程序，再用 `run.bat` 或 `main.py` 重新启动，启动前的 DPI 设置才会生效。

DPI 适配实现在 `src/display.py`，与聊天内容和 API 调用独立。新增界面时应使用这一模块，避免只放大字体、遗漏行高或重复缩放。依据：[Windows 进程 DPI 感知设置](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)、[Tk scaling 说明](https://www.tcl-lang.org/man/tcl8.5/TkCmd/tk.htm)。

## 数据流

选择聊天及日期，点击同步后读取未保存的部分。素材优先复用本地副本，无法读取的表情可从消息自带的微信 CDN 下载完整文件。先检查动静态、大小并去重，经确认后再将待解读素材发送给 DeepSeek。成功结果写入本地资料。提问时，RAG模式提供检索证据、素材词典和压缩历史；全文模式读取全部已存消息，容量不足则排除更早整条消息并提示覆盖范围。两种模式都不重新解码或上传已识别图片。

「API 设置 → 模型与推理 → 单次上下文上限」默认 1,000,000 token，可在 8192–1000000 内调整。这是输入及预留输出的总预算，与控制回答长度的 max_tokens 不同。「单次输入上限」默认 800,000 token，可在 4096–800000 内调整；实际可发送量还受窗口余量、回答空间及请求体大小限制。无论如何另留至少25%的窗口余量和回答空间，并检查最终 UTF-8 请求体不超过32MiB。这些是本地保守限制，不是服务商额外承诺的接口上限。

使用随源码保存的官方 DeepSeek V4 / V4.1 分词器在本地估算正文、素材词典、系统提示词、问题及问答历史；实际计费量以服务端为准。超过任何输入预算会在发送前显示提示，在回答开头和本轮引用中保留裁切说明。最新单条消息仍无法完整容纳时，本次不发送。仅在服务明确拒绝过长输入时，进一步缩小较早记录后最多重试两次；普通超时和网络错误不自动重发。文字分析使用流式接收，允许最长约30分钟处理时间、10分钟无数据等待（时限在读取数据前后检查）。支持服务端保活与思考阶段进度；回答片段逐步显示并自动保存。中断、超时或达到输出上限时，保留问题、旧对话及已收到片段，明确标记为未完成，不把片段加入后续模型历史，也不自动重发；服务端可能已处理并计费，客户端报错不代表未扣费。非流式素材解读仍使用原有180秒总等待及30秒无数据超时。容量依据：[DeepSeek 模型参数](https://api-docs.deepseek.com/quick_start/pricing/)、[官方分词器说明](https://github.com/deepseek-ai/deepseek-recipe/blob/main/docs/tokenizer.md)。

原始资料层保留 zlib 压缩的 XML（SQLite 的 message_payloads 表）以及 data/assets 中的原始素材和可提交副本；若源文件经过解密，还保留对应的 source.bin。可检索文字层保存结构化 AI 解读和按天文本。原始 XML 中的地址、密钥、尺寸、平台字段不会加入文本存档或模型上下文；普通文字消息中引用的 XML 保持原样。压缩并不等于加密，原始资料只保存在本机。

API 和微信数据库密钥通过 Windows DPAPI 加密保存在 `data/`，可沿用同一 Windows 用户下的已有密钥；也支持 `DEEPSEEK_API_KEY` 环境变量。不要把密钥写入源码。

## 图片、静态表情与 API 选项

- 在「API 设置 → 模型与推理」中选择文字模型 `deepseek-flash` / `deepseek-v4-pro`，配置 `thinking.type`、`reasoning_effort` 和 `max_tokens`；默认保持关闭思考。
- `max_tokens` 是思考与正式回答共享的总输出预算。填0或自动时，开启思考的最终文字分析预留131072 token（128K），关闭思考的文字分析为3500；手动可设置512至393216 token（384K）；辅助规划、摘要与图片解读沿用较小预算。手动填写的值优先，输入容量会按实际输出预算重新计算。较高预算可能增加耗时和实际用量，并不保证复杂问题一定在上限前完成；如果希望直接作答，可关闭思考并按需手动设置正文长度。输出触顶时保留已收到内容、明确是否尚无正文，不自动重发或自动接续计费。
- `reasoning_effort` 支持默认、`none`、`low`、`high`、`max`。开启思考时不能同时选择 `none`；关闭思考时不能选择 `low/high/max`。
- `messages` 自动根据问题、检索结果或图片组装。「messages 预览」显示请求结构，可通过附加系统提示词和图片提示词调整对应的 system 内容。
- 图片解读使用官方文档列明支持视觉的 `deepseek-flash`；文字模型选择 Pro 不会把不受支持的图片请求发送给 Pro。
- 普通图片严格要求 `50 × 1024 < 字节数 < 3 × 1024 × 1024`；静态表情取消下限，要求 `0 < 字节数 < 3 × 1024 × 1024`。解密后和转换后都检查，3 MB 边界不处理。
- 微信数据库里的「动画表情」也可能是静态文件，按完整素材的实际帧数判断。多帧 GIF、WebP、APNG 均跳过 VLM、不抽帧；单帧 GIF 可以识别。表情只使用完整文件，不使用缩略图代替，以免把动图误判为静态。
- 表情先在本账号 business/emoticon/Persist、PersistStore 和 cache/*/Emoticon 中按 MD5 查找。本机缺失、加密不支持或文件损坏时，默认回退到该条消息自带的微信 CDN 原始地址；只处理当前聊天及所选日期。可在「API 设置 → 图片与表情」关闭回退或调整「表情下载并发数」，默认 8，范围 1–200，与 VLM 并发独立。
- 重复表情合并下载，校验图片格式、原消息 MD5 和实际帧数后，按 SHA-256 缓存完整文件；解密使用消息中已有的 AES 密钥。地址仅允许腾讯域名并检查重定向；下载限制超时和大小。优先 HTTPS；对于消息原本保存的 HTTP 地址，HTTPS 连接失败时可重试原始 HTTP 地址，仍校验文件 MD5。过期、下载失败或校验不通过时保留占位，下次同步可重试。
- 普通图片读取本机已有的原图、缓存图或缩略图；专用 wxgf 容器在本机通过 FFmpeg 转为 JPEG。素材首次取得后按 SHA-256 保存一份本地副本，微信缓存清理后已有解读仍可检索，接口失败可直接用本地副本重试。
- VLM 输出描述、可见文字、数字与日期、可能语气、关键词及不确定内容。表情语气明确属于推测，不等于发言者已经同意或承诺。图上没有时区的时间保留原文；消息时间始终为北京时间。
- 完全相同的素材跨聊天、日期复用一份成功解读。内部使用完整 SHA-256；微信 MD5 只有与实际文件校验一致才用于快速复用。仅视觉相似的不同文件不自动合并。
- 更换模型或提示词不会自动重跑已完成素材。主界面「重新识别本范围已缓存素材」才会生成新版本，更新关联的消息和日期文本，旧版结构化解读继续保留。
- 每条发送事件独立保留，导出文件和回答模型的素材词典对同一素材只提供一份解读。检索命中素材关键词后，仍限定到当前聊天和日期内的发送记录，并通过消息编号引用。
- 未下载、解密失败、网络/API 错误保留状态，下次点击同步重试，不阻断文字同步。大小不符、动态素材不反复识别。同一素材正在处理时，其他任务不重复调用；异常中断后任务占用最长十分钟过期。
- API 未配置时不进行新识别；本地已经存在的成功结果仍可复用。旧版本的成功图片解读保留，遇到相同可校验图片时沿用缓存；旧版未留存的原文件无法凭空补回。
- 在 API 设置的「图片与表情」页设置 VLM 并发数，范围 1–200，默认 200。并发的是不同素材的模型请求；本机读取、格式检查和保存索引仍按顺序进行。
- 每次同步、重试或手动重新识别，均先准备素材（含允许的 CDN 下载）、排除动态和大小不符的文件并去重，再弹出 VLM 确认框，列明聊天、北京时间日期、模型、需发送的不同素材数及并发数。确认前不调用 VLM；取消后文字和下载准备好的本地素材保留，下次同步会重新询问。只有缓存复用或没有符合条件的素材时不需要模型调用，也不弹窗。
- 并发请求遇到密钥、余额、限流或网络错误时停止提交新请求；已经发出的请求会结束并保存可用结果，未完成的素材下次确认后可继续。
- 本地目录索引及解码失败记录保存在 `data/source-cache.sqlite3`。未变化的目录复用文件清单；同一文件、同一解码条件下的失败会跨消息和运行复用，不重复读入试解。文件大小、修改时间、本地表情密钥或解码版本变化后会重新尝试。勾选「重新检查已存日期」可让本次任务重新尝试失败文件，同一批内仍去重。
- 不为未知表情自动扫描微信进程密钥；只尝试消息内的已有密钥和已保存的本地密钥。本机和 CDN 均无法取得可校验完整文件时保留占位；VLM 调用前确认及 200 并发上限保持有效。

同步任务在开始时固定所选聊天与日期；文字导入、待处理素材和本次按天文本导出均受同一范围限制。没有有效范围时不进行素材识别。素材进度会显示聊天名、北京时间起止日期，以及该范围的待处理消息数。这个数包括可能跳过或复用的素材消息，不等于模型调用次数。原文的「预览日期」只控制浏览；同步仍使用左侧起止日期。首次定位本机素材时可能枚举共享缓存文件名，这一步不代表识别或上传了其他聊天的图片。

目前语音和其他附件尚未解析。历史范围受本机已有消息及所选起止日期限制。微信升级可能需要适配读取组件。

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Vision](https://api-docs.deepseek.com/guides/vision/)。

### 引用回复压缩脚本

`appmsg/type=57` 自动转换为「引用回复、回复正文、被引用者、被引用原话」。图片、表情等非文本引用仅保留类型占位，不猜测内容；普通文本中引用的 XML 和其他卡片类型不变。原始 XML 压缩保留在原始资料层，精简文字用于本地索引、模型上下文及按天文本。历史记录首次启动时自动转换一次，已有按天文本会通过更新队列刷新。

也可直接运行独立脚本，备份并转换现有存档、立即刷新按天文本：

```powershell
& 'D:\conda\python.exe' 'D:\pythonprograms\chat\convert_replies.py' --migrate
```

转换单个 UTF-8 XML 文件或包含消息 XML 的文本副本（输入文件保留）：

```powershell
& 'D:\conda\python.exe' 'D:\pythonprograms\chat\convert_replies.py' --input 'D:\pythonprograms\chat\work\reply.xml' --output 'D:\pythonprograms\chat\work\reply.txt'
```
