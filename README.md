# 微信聊天分析助手

<p align="center">
  <img src="resources/branding/logo.png" width="112" alt="微信聊天分析助手 Logo">
</p>

**把微信聊天记录整理成可检索、可追问、可核对的本地资料库。**

还在逐张截图，把聊天内容交给 AI 分析？微信聊天分析助手可以按聊天和日期提取本机记录，将图片、静态表情转换为文字，再结合 DeepSeek 完成总结、检索和连续问答。

适合回顾群聊讨论、整理项目进展、查找约定与决策，也可以用来梳理个人对话中的话题和互动。每次处理一个群聊或联系人，分析范围由你选择。

> Windows 桌面应用 · Python 源码运行 · DeepSeek API
>
> 当前 RAG 使用关键词检索与前后对话补充，尚未提供向量语义检索。

## 主要功能

- **按范围保存聊天**：选择一个群聊或联系人及起止日期，以北京时间处理消息，按天增量保存 UTF-8 文本。
- **图片与静态表情解读**：将符合条件的素材交给视觉模型识别，保存描述、可见文字和关键词，供后续检索。
- **本地缓存复用**：已保存的历史日期、重复素材和成功解读可复用；提问直接读取本地资料，无需反复解码微信记录。
- **两种分析方式**：用 RAG 检索具体问题，或用全文分析梳理一段时间内的整体讨论。
- **连续问答与证据引用**：保存不同范围下的会话，回答附带消息引用和实际覆盖信息，可导出 Markdown。
- **现代桌面界面**：采用 Fluent 2 / Win11 风格的浅色界面，适配高 DPI、多显示器与可滚动操作区。

## 运行环境

- Windows 10 / 11。
- Python 3.11 或更新版本，建议使用 64 位版本，并确保包含 Tkinter。项目已在 Python 3.11、3.13 环境下验证。
- 读取新记录时，需要在本机登录电脑版微信，并保留相应聊天记录。当前读取组件面向使用 `xwechat_files/<账号>/db_storage` 数据结构的微信；微信更新可能影响兼容性。
- 使用 AI 问答或新增图片解读时，需要可用的 DeepSeek API Key 和网络连接。

本项目直接运行 Python 源码，无需打包。未配置 API 时，仍可保存文字记录、浏览本地原文及复用已有的图片解读。

## 快速开始

下载或克隆完整项目后，在项目根目录打开 PowerShell。

### 1. 创建环境并安装依赖

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

以上命令无需激活虚拟环境。请保留完整的 `src/` 和 `resources/` 目录；其中包含界面资源及本地 token 估算所需的分词器数据。

### 2. 启动应用

```powershell
.\.venv\Scripts\python.exe main.py
```

如果已有 Python 或 Conda 环境，也可以在该环境安装依赖后运行 `python main.py`。

根目录的 `run.bat` 使用固定的解释器路径；如需双击启动，请先将其中的 Python 路径改为自己的实际路径。

### 3. 完成首次配置

1. 保持电脑版微信已登录，打开应用。
2. 在 **API 设置** 顶部填写 DeepSeek API Key，保存设置。
3. 点击 **从微信刷新聊天列表**，切换群聊或个人分类，选择一个聊天。
4. 设置起止日期，点击 **聊天解码并储存**。
5. 若有待识别图片，核对确认框中的聊天、日期、模型及素材数量，确认后开始识别。
6. 在原文栏检查保存结果，再选择 **RAG 检索** 或 **全文分析**，输入问题。

起止日期均包含在范围内，消息时间统一使用 **北京时间（UTC+8）**。原文栏的预览日期只控制浏览，不会改变左侧的同步与分析范围。

## 可以问什么

| 场景 | 示例问题 |
| --- | --- |
| 群聊总结 | 总结这周讨论的主要事项，列出达成的结论与仍有分歧的问题。 |
| 项目跟进 | 关于发布计划，谁负责什么？有哪些明确的截止日期？请引用原文。 |
| 查找约定 | 大家什么时候决定改用新方案？整理提出、反对和最终确认的过程。 |
| 个人对话 | 这段时间对方主动发起了哪些话题？请按日期列出原文依据。 |

分析只覆盖**本机已保存且位于所选聊天、日期内的资料**。模型对语气、态度或关系的判断属于推测，应结合引用原文核对。

## 如何选择分析方式

| | RAG 检索 | 全文分析 |
| --- | --- | --- |
| 适合的问题 | 查找某件事、某个人、某个话题，衔接连续追问 | 梳理整段讨论、总结整体变化、检查遗漏与矛盾 |
| 提供给模型的原文 | 当前范围内全部关键词命中，以及附近的前后对话 | 当前范围内全部已保存消息 |
| 连续问答 | 保留近期问答，对较早历史生成并缓存摘要 | 携带受容量限制的近期问答 |
| 超过容量时 | 先减少附带历史，再缩小前后对话窗口；命中原文本身仍超限则停止发送 | 按整条消息移除较早记录，保留连续的较新部分，并显示实际覆盖范围 |

**当前 RAG 是关键词检索，不包含 embedding 或向量语义搜索。** 程序会结合问题与问答历史规划关键词，再在本地检索。每个命中默认补充前后各最多 20 条消息，单侧不超过 15 分钟，连续消息间隔超过 5 分钟时分段；重叠窗口会合并。

全部关键词命中的正文及已保存素材解读都会保留。前后对话可能因容量不足而减少，界面与引用会区分命中消息、补充上下文及实际覆盖范围。时间相邻不一定属于同一话题，提供全部命中也不代表读取了所选日期内的全部讨论。

分块和索引更新在本地完成，不调用大模型；所有聊天共用一个检索库，按账号、聊天及日期隔离查询，无需逐个群单独建库。问答时的关键词规划和历史摘要会调用 API，因此 RAG 的实际用量取决于命中数量、日期范围和会话历史。

## API 设置

当前接入 DeepSeek API，设置项位于 **API 设置 → 模型与推理**：

| 设置 | 用途 |
| --- | --- |
| `model` | 文字分析可选 `deepseek-flash`、`deepseek-v4-pro`；图片解读使用 `deepseek-flash`。 |
| `thinking.type` | 选择默认、开启或关闭思考；程序默认关闭思考。 |
| `reasoning_effort` | 支持默认、`none`、`low`、`high`、`max`，需与思考模式兼容。 |
| `max_tokens` | 思考与正式回答共享的总输出预算；填写 0 表示自动。 |
| 上下文与输入上限 | 控制单次请求的本地容量预算，程序还会预留输出空间并检查请求大小。 |
| 系统提示词 | 为回答补充要求；图片提示词在“图片与表情”页单独设置。 |

`messages` 由程序根据问题、原文、素材文字及会话历史自动组装，可在 **messages 预览** 中查看结构示例。

也支持 `DEEPSEEK_API_KEY` 环境变量；设置该变量时，优先使用环境变量中的密钥。API 用量与费用以服务方返回为准，模型及接口说明可查阅 [DeepSeek API 文档](https://api-docs.deepseek.com/)。

## 图片与表情

在 **API 设置 → 图片与表情** 中启用或关闭识别，并配置提示词、VLM 并发数及表情下载选项。

| 内容 | 当前处理方式 |
| --- | --- |
| 普通图片 | 严格满足 `50 KiB < 文件大小 < 3 MiB` 时可识别。 |
| 静态表情 | 严格满足 `0 < 文件大小 < 3 MiB` 时可识别，包括实际为单帧的 GIF。 |
| 动态表情 | 根据完整文件的实际帧数判断；多帧 GIF、WebP、APNG 跳过识别。 |
| 语音、视频及其他附件正文 | 暂不解析，保留相应消息或占位信息。 |
| 缺失或无法解码的素材 | 保留状态或占位，不阻断文字保存。 |

程序先准备本地素材、检查格式并去重，再弹出 VLM 调用确认框。**确认前不会向视觉模型上传图片。** 取消后，文字及已经准备好的本地素材仍会保留。

本机缺失的表情默认允许从该条消息自带的微信 CDN 地址下载完整文件；下载发生在素材准备阶段，可在设置中关闭。图片解读会保存为本地文字，后续文字问答复用这些解读，不重复上传已识别图片。

相同文件可跨日期、跨聊天复用成功解读。更换模型或提示词不会自动重跑历史素材；需要更新时，点击 **重新识别本范围已缓存素材**，确认后生成新版本。

## 增量保存与会话记录

已成功保存的历史日期会复用，只补充未覆盖日期及当天新增消息。若需要补入某个历史日期后来新增或恢复的记录，可勾选 **重新检查已存日期** 后再次解码。只有发生变化的日期文本和索引片段需要更新。

切换聊天或日期不会删除已有存档。重新启动会恢复本地列表、保存范围及会话，不会自动解码聊天或发送模型请求；读取新记录需手动操作。

问答会按聊天、日期范围及会话分别保存，支持连续追问和 Markdown 导出。网络中断时，问题及已收到的回答片段会保留，并标为未完成；重启不会自动重发。若 API 返回了思考内容，导出文件会单独记录这部分内容。

## 数据存放与隐私

默认数据目录为项目根目录下的 `data/`，与启动时所在目录无关。

| 路径 | 保存内容 |
| --- | --- |
| `data/messages.sqlite3` | 已导入消息、同步状态和原始消息资料 |
| `data/transcripts/<聊天标识>/YYYY-MM-DD.txt` | 按天保存的 UTF-8 文本及素材解读引用 |
| `data/assets/` | 去重后的本地图片、表情及处理所需副本 |
| `data/analysis/` | 结构化素材解读及历史版本 |
| `data/rag.sqlite3` | 本地检索索引与历史摘要缓存 |
| `data/conversations.sqlite3` | 问答、草稿、引用及未完成请求 |

原始微信数据库以只读方式访问。提问会将问题、相应原文、素材解读及必要的问答历史发送给 DeepSeek；图片识别另按确认的素材批次发送。使用表情 CDN 回退时还会访问微信素材地址。

**消息、导出文本和图片文件默认未加密。** API 密钥与微信数据库密钥使用 Windows DPAPI 加密保存，并绑定相应 Windows 用户环境。备份时建议保留整个 `data/`；迁移到其他电脑或 Windows 用户后，通常需要重新填写 API Key 并重新获取微信读取密钥。分享源码时请排除个人数据、导出记录及密钥文件。

如需独立存放数据，可在启动时指定：

```powershell
.\.venv\Scripts\python.exe main.py --data-dir "E:\ChatAnalysisData"
```

## 常见问题

### 找不到某个群聊或联系人？

聊天列表默认仅显示至少 **1000 条消息且正文体积至少 50 KiB** 的聊天，并按内容大小从大到小排列。可取消该筛选，检查“群聊 / 个人”分类，并刷新微信聊天列表。

### “微信数据根目录”应该填什么？

自动定位失败时，在 **API 设置 → 微信目录** 填写包含账号子目录的数据位置，例如 `E:\xwechat_files`。其下通常存在 `<账号>\db_storage`。请根据微信实际的数据保存位置填写。

### 出现 `No module named ...`？

依赖需要安装到**实际启动程序的那个 Python 环境**。使用本文的虚拟环境启动方式时，重新执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Tkinter 由 Python 安装器或 Conda 提供，无法通过本项目的 pip 依赖安装。

### 能检索手机上或已删除的历史消息吗？

只能处理本机微信中实际存在并成功导入的记录。程序不恢复已删除消息，也不能补齐本机未保存的图片或聊天历史。

### 输入过长，或者回答只显示了思考内容？

缩小日期范围，或把问题限定到具体事项。全文分析可能减少较早消息，RAG 可能减少前后对话；请查看本轮实际覆盖信息。RAG 若仅关键词命中就已超限，会停止发送。

思考与回答共用 `max_tokens` 预算，思考可能耗尽输出空间。可关闭思考，或按需调整总输出预算后手动重试。已接收内容会保留；网络错误或输出触顶不会自动重新发送付费请求。

### 高分辨率屏幕需要额外设置吗？

程序会根据 Windows 显示缩放调整字体、控件和列表，并在主窗口移到不同 DPI 的显示器时更新。空间不足时可滚动侧栏及设置表单。修改系统缩放后，若显示异常，可先关闭应用再重新启动。

## 开发与验证

入口为 `main.py`，应用代码位于 `src/`，测试位于 `tests/`。修改后可以直接重新运行源码。

```powershell
# 运行测试：使用模拟接口，不发送真实聊天或图片
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# 检查界面启动：使用独立数据目录，不连接微信或调用模型
.\.venv\Scripts\python.exe main.py --smoke-test --data-dir work\ui-smoke
```
