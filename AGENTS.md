# Project conventions

- Active project root: `D:\pythonprograms\chat` (relocated from the Desktop project).
- Maintain and run the Python source directly. Do not package executables unless the user explicitly requests it.
- Interpreter: `D:\conda\python.exe`. `D:\conda\_conda.exe` is the Conda manager, not the Python interpreter.
- Start with `D:\conda\python.exe main.py` or `run.bat`.
- Application code lives in `src/`; tests live in `tests/`.
- Application branding is 微信聊天分析助手. The selected-range decode/save button must read 聊天解码并储存. Shared colors and ttk appearance belong in src/ui_theme.py; its Display.style hook reapplies custom dimensions/fonts on monitor DPI changes. Preserve existing controls, saved scopes, workflows and scroll access during visual changes.
- The user-approved logo is resources/branding/logo.png. Preserve its supplied pixels; app_branding.py creates only in-memory display sizes, sets native window icons and shows the header logo. Follow the existing Display DPI scale/theme refresh hook; cache Tk images and retain references. Missing/corrupt optional artwork must not block startup or reading local records.
- Use Fluent 2 / Win11-inspired light styling: neutral surfaces, blue accent, 4px rounded controls, 8px rounded cards, clear focus/hover/disabled states. Rounded ttk image elements live in src/fluent_widgets.py and are generated with the existing Pillow dependency, cached per monitor scale, retaining native ttk bindings. Keep the decode/save action fixed below the scrolling sidebar; auto-hide text/list scrollbars only when content fits. Native DWM corner/caption styling must be OS-version gated and fail gracefully on Windows 10; do not claim native Mica or WinUI support.
- Run relevant checks with `D:\conda\python.exe -m unittest discover -s tests -v`.
- Runtime data belongs in `data/`. Preserve existing messages, settings, and encrypted keys. Never print or commit them.
- Use `work/` for temporary files and test data.
- The old `2026-10-14/` tree is retained as a historical copy; do not edit or rebuild it for ordinary changes.
- Keep all message access read-only against the original WeChat databases. Only manually selected chats enter the local retrieval index.
- Display readable chat names instead of internal WeChat identifiers. When the local group name is missing, explicitly label it as unnamed. Do not offer local display-name editing or apply old name overrides.
- The UI selects exactly one conversation and a start/end date (both included). Hard-limit search, neighboring evidence, statistics and VLM to that chat and date range. Switching chats/ranges must retain all archived data.
- Capture the sync scope once per job and pass it explicitly through material queries, VLM and daily exports. Missing media scope must fail closed, never fall back to all selected history. Ordinary sync flushes only dirty days in that chat/date scope; global export remains available for migrations and startup archive recovery.
- Startup restores local catalog/metadata and messages without automatic message import. Only an explicit sync reads the selected range from WeChat. Search never creates a WeChat reader.
- Maintain durable range coverage and message-ID deduplication. Reuse covered historical dates; import only gaps, with a five-minute overlap for today's live tail. Full history rechecks are explicit.
- Save UTF-8 text incrementally under data/transcripts/<chat-id>/YYYY-MM-DD.txt. Rewrite only changed days atomically; preserve a durable dirty queue. Image results must also update text exports. Mark range coverage only after all source shards and text writes succeed.
- Use Beijing time (UTC+8) consistently for message timestamps, date filters, sync timestamps, exports and model date interpretation.
- Enable Windows DPI awareness before creating Tk. Use src/display.py for monitor DPI, 96-DPI layout dimensions, font metrics, work-area bounds and monitor-change updates; do not apply another independent scaling factor. Scale Treeview row heights and columns together with fonts. Keep sidebar and settings controls reachable by scrolling on constrained work areas.
- VLM processing is restricted to the selected chat and dates. Ordinary images must be strictly larger than 50*1024 bytes and smaller than 3*1024*1024 bytes. Static stickers have no lower bound and must be smaller than 3*1024*1024 bytes. Detect animation from the actual full file (including GIF/WebP/APNG), never from the database label or a thumbnail; animated media must never reach VLM. Never upload real images during tests.
- Prepare local assets and deduplicate before VLM. Every batch, including explicit reanalysis and retries, requires the user's confirmation of the concrete chat/date/model/unique-asset count before any VLM request. Missing approval denies sending. Tk dialogs must run on the UI thread. Cancellation preserves text and cached inputs for a later approved run.
- VLM network requests run concurrently with a configurable integer limit 1–200 (default 200), and bounded in-flight submissions. Keep source readers and index writes serial; use asset claims for cross-job deduplication. On stop or fatal API errors, stop submitting new requests, settle existing calls and release claims. Tests must explicitly approve synthetic batches and mock all API calls.
- Cache local directory entries by directory modification time and failed sticker decoding by file path/size/mtime, decoder version and key conditions in data/source-cache.sqlite3. File/key changes or an explicit historical recheck permit retry; repeated identical failures must avoid file reads and status rewrites. Unsupported stickers must not trigger automatic process-key scans; use existing local/XML keys only.
- The user authorized WeChat CDN fallback on 2026-10-15. Prefer retained/local full stickers; when unavailable or undecodable, download only original cdnurl/encrypturl from messages in the frozen chat/date scope. Validate Tencent hosts and redirects, bound time/bytes, verify source MD5 and actual frames, never substitute thumbnails. Downloads run concurrently (default 8, configurable 1–200), merge repeated stickers and persist verified files before VLM confirmation. Invalid/expired resources retain placeholders and may retry later. CDN preparation does not authorize VLM calls.
- Conversations are persisted separately in data/conversations.sqlite3, isolated by exact chat/start/end scope and selectable session. Preserve them during local preview, day navigation and sync. Every follow-up rereads the saved scoped messages; model history is bounded to 10 rounds/20000 characters and is not factual evidence. Previous citation labels must not masquerade as the current round's labels. Render assistant Markdown natively without executing HTML or fetching images; export original Markdown with each round's references.
- Full-context analysis reads every saved message in exactly one frozen chat/date scope, with full searchable message text and deduplicated saved material analyses. Do not apply retrieval hit counts, keyword filtering, neighbor sampling or per-message text caps in full mode. Use a consistent SQLite read snapshot and corresponding local DeepSeek tokenizer. Budget all input/output and safety margin. If needed remove only whole oldest messages, retaining a contiguous newest suffix; never delete archive data. Inform the user and persist actual coverage. Do not split full-context analysis into batches. Tests and dry runs must mock model calls and never upload real messages.
- The user authorized backed-up implementation of lexical RAG and history compression on 2026-10-15. Keep full analysis available; never describe keyword RAG as vector/semantic search. RAG captures scope/session, builds a local transactional index in data/rag.sqlite3, reuses unchanged half-hour buckets and rebuilds changed buckets only. Use exact scoped statistics and deduplicated asset descriptions; keep all original archives.
- On 2026-10-16 the user requested every keyword match be sent to the LLM and removal of the separate RAG token ceiling. RAG must provide all matching records and complete saved material descriptions in chronological order, without chunk-count caps, hit limits or source excerpts. Empty keywords match all messages in the frozen query dates. Keep global input/context/output-margin and request-byte checks; reduce accompanying Q&A history first if necessary, then fail with explicit counts/limits rather than omit matching source records. Never auto-retry a smaller subset, even on a context rejection. Mark all_matches_included separately from coverage of the entire selected scope. Remove the RAG budget UI/config behavior; accept obsolete Python budget arguments only as ignored compatibility inputs. Tests must verify full messages above the old token/count limits, scoped isolation, complete materials, and capacity failure without a partial analysis request.
- RAG source indexing is shared across date ranges in one database, keyed by account-qualified chat ID and message ID. Query records, neighboring evidence and counts must explicitly filter the frozen chat/date range. Retain cached records outside a sync range, including partially covered buckets; certify complete indexed ranges from exact local snapshots only. Migrate legacy range namespaces transactionally, deduplicating source records without touching memories, source archives or conversations. History keys remain exact scope/session hashes, independently of the shared source namespace.
- RAG must include conversational context around every exact match: up to 20 preceding and 20 following events, each side within 15 minutes, stopping at adjacent-message gaps over 5 minutes. Merge overlapping/touching windows within a continuous segment; keep chronological (timestamp, seq, id) ordering, deduplicate messages and preserve complete text/materials. Read matches, exact statistics, metadata and neighbor payloads in one index snapshot, always within frozen chat and narrowed query dates. Label keyword matches and supplementary context separately and supply passage reference boundaries; temporal adjacency is not proof of a shared topic or a complete conversation. Count matches independently from added context, preserve every match. On local capacity overflow, first reduce accompanying Q&A history, then narrow supplementary windows from 20 to 10/5/2/1/0 events per side using only the original captured snapshot; never omit or excerpt a keyword match or its material description. Clearly expose initial/actual window, original/retained/omitted context counts in the model input, progress, answer and saved coverage. A zero window must explicitly mean matches only. If matches alone still exceed token/byte capacity, fail before final analysis without a partial request; never auto-retry a smaller subset after a model/network rejection. Keep this behavior out of full-context mode, preserve old saved reference payloads and mock every model call in tests.
- RAG history keeps up to three recent rounds, caches a bounded summary of older completed turns by exact scope/session/prefix hash, and may retrieve older exchanges. Summaries/history are reference material, never current factual evidence. New older turns alone update cached summaries. Guard planner, summary and answer input budgets before sending, retain original Q&A and successful memory on failures, and preserve streaming/partial-reply persistence. RAG tests mock every model call; local indexing never invokes WeChat or VLM.
- Use a default input ceiling of 800000 tokens, reserve at least 25% of the configured context window in addition to output, and check the exact serialized UTF-8 request against a 32 MiB local payload ceiling (separate from the token ceiling; the previous 2 MiB cap was too small). The input ceiling is editable (4096–800000). Only explicit HTTP 413/context-length rejection permits automatic shrinking (at most two retries); keep the frozen chat/date scope. Do not auto-retry ambiguous timeouts/network failures. Full-context text analysis uses SSE streaming, a 30-minute overall deadline check and a 10-minute socket inactivity timeout so large-input prefill and thinking do not hit the legacy short timeout. Parse keep-alive comments, UTF-8 fragments, reasoning-only deltas, usage-only frames and [DONE]. Persist answer fragments while receiving and on disconnect; show them explicitly as incomplete and never include them in model history. Keep the legacy 180-second/30-second limits for non-streaming VLM requests.
- Persist each analysis question and its scope/session before starting network work. Save successful replies, references and actual input coverage transactionally in conversations.sqlite3 before UI rendering, using the request id to prevent duplicates. Keep pending/failed requests and session drafts across restarts, autosave typing after a short debounce and flush drafts on session/scope changes and close. Restore unfinished questions without automatically resending them; preserve all preexisting sessions and turns.
- The user requested provider-returned model thinking in Markdown exports on 2026-10-16. Capture final-analysis reasoning_content separately from answer text in both full and RAG modes; persist cumulative reasoning fragments in requests.partial_reasoning and completed reasoning in the turn payload. Export complete or interrupted thinking verbatim in a separately labeled API-returned section, marking unfinished responses explicitly, including thinking-only failures. Do not add reasoning to subsequent model history, summaries or factual sources. Do not fabricate thinking for older responses or responses without reasoning_content. Migrations must preserve all existing conversations and requests; tests must use synthetic responses only.
- Retrieve oldest messages chronologically for earliest/first-occurrence questions. Compute exact COUNT/MIN/MAX over the complete scoped and filtered local query in one read snapshot, independently of returned message limits; include actual first/last witnesses and expose formatted Beijing timestamps to the model. Distinguish selected date boundaries, saved-message extrema, query-match statistics and limited supplied evidence. Never describe exact statistics as truncated or infer the chat's full WeChat history from selected local records. Neighbor evidence also respects any narrower dates requested in the question.
- Keep two local layers: compressed raw XML and content-addressed source/input files in data/assets; versioned structured AI analyses in data/analysis and daily text in data/transcripts. Do not expose download URLs, AES keys or raw media XML in retrieval text. Keep ordinary text that quotes XML unchanged.
- Compact appmsg type 57 replies into reply text, quoted sender and quoted content; preserve raw XML in message_payloads. Apply the same conversion on import and to existing local records, maintaining FTS and dirty-day exports. Do not convert other appmsg cards or XML quoted in ordinary text.
- Original previews have raw and searchable tabs, with an independent Beijing-date picker and 200-message pages. Day/page navigation must never narrow the saved retrieval/sync scope or read WeChat. Bound rendered text lengths while retaining complete source records locally.
- Deduplicate by actual file SHA-256; source MD5 aliases must first be verified against the file. Reuse successful analyses across chats, dates, model/prompt changes and API-key absence. Explicit reanalysis alone creates a new version and updates linked messages/days. Use a database claim to avoid concurrent duplicate calls.
- Text exports and model context keep each sending event, with one material dictionary entry per unique asset. Failed API requests should retry from retained local inputs without reopening WeChat. Preserve existing successful analyses and original user records during migration.
- DeepSeek Flash is the image model; text requests may use Flash or V4 Pro. Respect the saved thinking/reasoning options and reject conflicting combinations.
- The automatic output budget for thinking-enabled final text analysis is 131072 tokens (128K), shared by reasoning and final answer; manual max_tokens supports 512–393216 tokens (384K, verified in current official Chat Completions documentation); the old 16384-token automatic text budget could end before any answer. Keep explicit user max_tokens authoritative, preserve saved thinking/effort choices and keep automatic auxiliary JSON/vision budgets at 16384. Reserve the actual output budget during full/RAG capacity checks. Explain the shared budget in settings and output-limit errors, preserve reasoning/answer fragments and never automatically retry a paid length-truncated request.
- Default chat-list filtering requires at least 1000 source messages AND 50*1024 stored body bytes, ordered by content bytes descending. Filtering is non-destructive and does not silently deselect hidden saved chats.
